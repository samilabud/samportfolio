Discount Club Platform – Multi-Tenant SaaS Booking System

A production, multi-tenant SaaS booking system built for a real client (Todd Ogryzlo / SNS Software), running two live domains — discountbnbclub.com and homestayclub.ca — from a single Next.js codebase deployed on Vercel. I own the full stack: schema design, passwordless auth, multi-tenant architecture, admin tooling, and email infrastructure.

  • Next.js
  • React
  • TypeScript
  • Tailwind CSS
  • MongoDB
  • Mongoose
  • Nodemailer
  • Vercel
Key features & architecture
  • Passwordless email verification: visitors register with an email, receive a 6-digit code (30-min TTL), and unlock booking only after verifying it
  • Booking request flow: verified users submit a detailed form (BnB name, dates, vehicle, price expectation), triggering a confirmation email to the user and a rich HTML notification to the business owner
  • Admin dashboard: a separate, code-verified admin login (allow-listed emails) protected by its own signed session cookie, with a full booking status workflow (pending → approved / rejected / contacted / completed) and a timestamped audit trail
  • True multi-tenancy: a single deployment serves two branded domains, detecting the host at runtime to theme colors, email copy, and favicon per domain, while tagging every DB record with its origin domain
  • Rate limiting & abuse prevention: MongoDB-backed rate limiting on registration/ verification attempts with TTL-based auto-expiry
  • Security: HMAC-SHA256 signed, stateless session tokens (no server-side session store) for both users and admins, with distinct scopes/TTLs (24h user / 8h admin) and HTTP-only cookies

Architecture & Dev Practices: Next.js 16 (App Router, API routes, edge-ready) + React 19 + TypeScript, MongoDB via Mongoose 9 (TTL indexes, compound indexes, connection pooling), Tailwind CSS 4, Nodemailer over SMTP with Ethereal test-inbox previews in dev, and a hand-rolled passwordless/OTP auth flow with signed opaque session tokens instead of a third-party auth provider. Email sends are awaited before responding to avoid Vercel killing the function mid-send, and a single runtime host-detection utility drives theming, favicons, email branding, and DB partitioning across both domains.

Damage Deposit Holder – Rental Deposit Dispute Mediation Platform

A full-stack web app that mediates rental damage-deposit disputes between renters, landlords, and a neutral admin. Instead of a deposit sitting privately between two parties, all communication and proof-of-payment happens on a shared, moderated record tied to a specific property.

Key features & architecture
  • Houses: landlords list rental properties, admin publishes them, and renters browse published listings
  • Subjects & threaded chat: each house has topic threads where renters and landlords exchange messages and image attachments (e.g. e-transfer receipts)
  • Admin moderation: every message starts unapproved until an admin reviews and approves it as part of the official record, with the ability to forward the full thread as an email transcript
  • Notifications: the first message in a new thread auto-emails the admin via Nodemailer/SMTP so disputes and proofs don't go unnoticed
  • Role-based accounts (renter / landlord / admin) via NextAuth credentials + JWT, plus a super-user flag for elevated admin management

Architecture & Dev Practices: Next.js 15 (App Router, Turbopack) + React 19 + TypeScript, MongoDB/Mongoose (Users, Houses, Subjects with embedded Messages), NextAuth.js credentials provider with bcrypt password hashing and JWT sessions, Tailwind CSS 4, Framer Motion and Headless UI for the UI, Nodemailer for transactional/admin email alerts, and react-dropzone for image/proof uploads. Server Components fetch data directly from MongoDB with explicit force-dynamic rendering for DB-backed pages, and API routes enforce role-based access control with server-side session checks.
